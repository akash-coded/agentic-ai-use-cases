# How-to · Product Managers and Product Owners

You do not need to write the code. You do need to specify, price and defend a system whose behaviour is
probabilistic.

## The three things to internalise

1. **Criteria are rates on a named set**, not pass/fail on a case. The set is the specification, and it
   must contain cases the agent currently fails.
2. **Abstention is a designed rate.** An agent that never declines is not confident, it is dangerous. Put a
   target band in the criteria.
3. **Cost per *resolved* task** is the number, not cost per task. Divide by the resolution rate before
   quoting anything.
