# Playbooks

Strategic and organisational. Where [runbooks](../runbooks/) are for incidents, playbooks are for
decisions — the meetings, the trade-offs and the conversations that determine whether an agent project
succeeds before anyone writes code.

---

| Playbook | For | Output |
| --- | --- | --- |
| 🔍 **[Running an agent design review](agent-design-review.md)** | Leads, architects, EMs | A scored decision with a named condition |
| ⚖️ **[Build, buy, or wait](build-buy-or-wait.md)** | Architects, PMs, sponsors | A recommendation with the cost stated honestly |
| 📐 **[Scoping an agentic engagement](scoping-an-engagement.md)** | Consultants, SAs, internal delivery | A one-page proposal with kill criteria up front |
| 🛑 **[Killing an agent project](killing-an-agent-project.md)** | Anyone who has to stop one | A clean stop that makes the next attempt fundable |

---

## The three questions that run through all four

**1. "What does it do when it doesn't know?"**
Design review, vendor evaluation, discovery call — this question tells you more about a system than any
architecture diagram. See [Abstention Budget](../frameworks/abstention-budget.md).

**2. "What rung is that evidence on?"**
Ends circular arguments instantly. "It works" is not a claim; "87% on a 130-case golden set" is. See
[Evidence Ladder](../frameworks/evidence-ladder.md).

**3. "What would make us stop?"**
Asked at the start, it is confidence. Asked at the end, it is a negotiation. See
[Killing an agent project](killing-an-agent-project.md).
